# TKT-0036: Source Document Tree View — Implementation Plan

## Overview

No per-source-document aggregation query exists today. The tree view requires a new read path that returns source documents with their current path, classification, candidate count, extraction count, and review status, which the React client assembles into a directory hierarchy.

## Layer 1: SQL read query (postgres adapter)

Add `list_source_documents()` to `PostgresImportReviewRepository` in `import_reviews.py`. The query joins:
- `source_document_paths` (WHERE `is_current`) → current path
- Latest `source_revisions` via LATERAL (copy `_REVIEW_SOURCE_LATERAL` pattern) → classification
- `LEFT JOIN (SELECT source_document_id, count(*) FROM import_candidates WHERE status='active' GROUP BY 1)` → candidate count
- `LEFT JOIN (SELECT ce.candidate_id ... FROM candidate_extractions ce JOIN import_candidates ic ...)` → extraction count
- `LEFT JOIN (SELECT subject_id, count(*) FROM review_items WHERE status='open' AND subject_type='source_document' GROUP BY 1)` → open review count

Returns flat rows: `{document_id, path, classification, candidate_count, extraction_count, open_review_count, missing}`. The client builds the tree from paths.

## Layer 2: Application models + service

Add to `application/import_reviews.py`:
- `SourceDocumentSummary` — frozen Pydantic model: `document_id, path, classification, candidate_count, extraction_count, open_review_count, missing_source`
- `SourceDocumentPage` — `{items, total, limit, offset}`
- `SourceDocumentListQuery` — `{requester, limit=100, offset=0}` (higher default limit since a tree needs the full corpus; no pagination filter needed initially)

Extend `ImportReviewRepository` protocol with `list_source_documents(query)`. Extend `ImportReviewService` with a `list_source_documents()` method (DM-only, same as runs/reviews).

## Layer 3: FastAPI endpoint

`GET /imports/source-documents` in `app.py` — mirrors `/imports/candidates` pattern: `limit`/`offset` bounds (default limit 200 to cover the 143-file corpus), `requester_role` + optional `character_id`. Response model `SourceDocumentPage`.

## Layer 4: Windmill proxy + client types

**`campaignClient.ts`:**
- Add `SourceDocument` interface: `{document_id, path, classification, candidate_count, extraction_count, open_review_count, missing_source}`
- Add `listSourceDocuments(limit?, offset?)` to `CampaignClient` interface
- Implement in both `HttpCampaignClient` (GET `/imports/source-documents`) and `WindmillCampaignClient` (add `"list_source_documents"` to the `ReviewBackendRequest` union)

**`backend/review_campaign.ts`:**
- Add `"list_source_documents"` to the re-declared `ReviewBackendRequest` union
- Add `list_source_documents → { method: "GET", path: "imports/source-documents" }` to the `route()` switch

**Tests:** extend `reviewCampaignBackend.test.ts` with a `list_source_documents` routing assertion.

## Layer 5: React tree view component

In `App.tsx`, add a `DocumentTree` component that:
- Fetches source documents via `campaignClient.listSourceDocuments()` in the `loadReviewWorkspace` Promise.all
- Builds a tree from the flat path list (e.g., `npcs/Arkin.md` → `npcs/` → `Arkin.md`)
- Renders with expand/collapse per directory
- Each document node shows: classification badge, candidate count, extraction indicator, open-review warning if any
- Clicking a document filters the candidate list to that source document's candidates
- The tree replaces the flat candidate queue as the left navigation in the review section; the candidate list below shows the selected document's candidates

**CSS:** add tree-specific styles to `index.css` (indentation, expand/collapse toggle, status indicators).
